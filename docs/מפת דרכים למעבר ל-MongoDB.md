# 🗺️ מפת דרכים: מעבר מלא ל-MongoDB (Phase 4 & 5)

מסמך זה מתאר את האסטרטגיה לניתוק התלות ב-Google Sheets ומעבר לבסיס נתונים רלוציוני/מסמכים (MongoDB) כבסיס נתונים ראשי.

## 🎯 המטרה
להחליף את Google Apps Script (GAS) בשרת Node.js (ב-Render) המחובר ל-MongoDB Atlas, תוך שמירה על Firebase כלוח הבקרה בזמן אמת.

---

## 🛠 שלבי המעבר

### שלב 1: שכפול כתיבות (Shadow Writing)
במקום לכתוב רק לגיליון ול-Firebase, השרת יתחיל לכתוב כל שינוי גם ל-MongoDB.
- **יעד**: יצירת `Audit Log` מלא ב-Mongo.
- **סטטוס**: ניתן להתחיל מיד לאחר פריסת שרת ה-API החדש.

### שלב 2: העברת הלוגיקה העסקית (Business Logic Migration)
העברת הפונקציות המורכבות מ-GAS ל-Node.js:
- חישוב עמלות.
- ניהול תורים ושיבוץ חכם.
- שליחת הודעות WhatsApp (כבר קיים ב-Bridge, רק צריך לחבר ל-Mongo).

### שלב 3: הפיכת MongoDB ל-Source of Truth
בשלב זה, ה-Admin Dashboard וה-Driver App יפסיקו לפנות ל-GAS לצורך כתיבה.
- **מעבר**: `POST` requests יעברו ל-`https://taxiwork-api.onrender.com`.
- **סנכרון**: שרת ה-Node.js יעדכן את Firebase (לצורך UI חי) ואת הגיליון (לצורך גיבוי בלבד).

### שלב 4: ניתוק הגיליון (Deprecating Sheets)
לאחר תקופת הרצה של חודש ללא תקלות ב-Mongo:
- הפסקת הכתיבה לגיליונות.
- שמירה על הגיליונות כ-Archives בלבד.

---

## 📊 השוואת ביצועים צפויה

| פרמטר | Google Sheets (המצב הקיים) | MongoDB + Firebase (המצב החדש) |
| :--- | :--- | :--- |
| **זמן תגובה (Write)** | 2-5 שניות | < 200 מילי-שניות |
| **זמן תגובה (Read)** | 1-3 שניות | < 50 מילי-שניות (Firebase) |
| **קיבולת נתונים** | מוגבל (עד 5M תאים) | בלתי מוגבל |
| **חיפוש ופילטור** | איטי (סקירה טורית) | מהיר מאוד (אינדקסים) |

---

## 🛡️ ניהול סיכונים
1. **אובדן נתונים**: במהלך המעבר, כל פעולה תירשם ב-3 מקומות (Sheets, Firebase, Mongo).
2. **זמינות**: שרת ה-Node.js ב-Render יוגדר עם `Keep-alive` ו-`Auto-restart`.
3. **אבטחה**: שימוש ב-JWT מורחב ו-IP Whitelisting לגישה ל-Database.

## ⏭️ הצעד הבא המיידי
מומלץ לבצע **Smoke Test** למערכת ה-Firebase הנוכחית לפני שמתחילים את הקמת שרת ה-Node.js עבור MongoDB.
