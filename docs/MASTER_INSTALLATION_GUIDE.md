# 🚀 מדריך ההתקנה וההפצה המלא (Master Installation Guide)

מדריך זה מאגד את **כל שלבי ההתקנה של המערכת** מרמת מסד הנתונים ועד לשרתי הענן ולסביבת ה-Frontend. מדריך זה מחליף גרסאות התקנה קודמות ומכיל את כל העדכונים (כולל תמיכה באופטימיזציות ובבסיסי הנתונים בענן).

---

## חבילה 1: מסד הנתונים בזמן אמת (Firebase Realtime Database)
פיירבייס משמש כעמוד השדרה של הסנכרון הרציף (לייב מפה, הזמנות לייב ומסרים) אל מול דפדפני הלקוחות, הנהגים והתחנה.
1. היכנס אל [Firebase Console](https://console.firebase.google.com).
2. פתח פרויקט חדש (למשל `taxi-bridge-prod`).
3. בתפריט הצדדי בחר **Realtime Database** וצור מסד באזור המועדף עליך (מומלץ אירופה – europe-west1 למהירות טובה בישראל).
4. **כללי אבטחה (Rules)**: גש ללשונית ה-Rules בפיירבייס והגדר את אינדקס האופטימיזציה כדי למנוע קריסת נתונים בלקוח:
   ```json
   {
     "rules": {
       ".read": "true",
       ".write": "true",
       "active_orders": {
         ".indexOn": ["status"]
       }
     }
   }
   ```
5. **מפתח מנהל מערכת:** לחץ על סמל גלגל השיניים ⚙️ -> **Project Settings** -> עבור ללשונית **Service Accounts** וייצר מפתח חדש (Generate new private key). מקבל קובץ JSON? שמור אותו אצלך בבטחה, נשתמש בו בשלב הבא.

## חבילה 2: המוח והגיבויים (Google Apps Script - GAS)
שרת ה-GAS מתפקד כאפליקציית הליבה למשימות, לחיובים וכמסד גיבוי היסטורי באקסל (Google Sheets).
1. פתח גיליון Google Sheets חדש ויציב שיישאר שם תמיד (מומלץ בחשבון יעודי לפרויקט).
2. בתפריט העליון, לחץ על **Extensions** (תוספים) -> **Apps Script**.
3. הדבק אל תוך הסקריפט את כל קבצי ה-`.gs` מתוך תיקיית ה-`GS` שבקוד המקור.
4. **הגדרות המערכת:** בסרגל הצד ב-Apps Script לחץ על הגדרות (⚙️) -> תחת **Script Properties** (נכסי סקריפט), הזן את 4 המשתנים למערכת:
   * `FIREBASE_URL`: כתובת ה-Realtime Database שיצרת בסעיף א'.
   * `FIREBASE_PRIVATE_KEY`: הדבק את כל תוכן קובץ ה-JSON ששמרת מפיירבייס.
   * `BRIDGE_API_KEY`: מחרוזת סיסמה סודית וחזקה (תשמש לתקשורת בין שרת הווטסאפ למוח).
   * `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`: אופציונלי אך מומלץ - על מנת לקבל אזהרות בזמן אמת לטלגרם אם השרת נופל.
5. **הפצה לפרודקשן**: בפינה העליונה לחץ **Deploy** -> **New Deployment**.
   * בחר סוג הפצה גישה לחשבון כ-**Web App**.
   * "Execute As": "Me" (החשבון שלך).
   * "Who has access": "Anyone" (כולם).
6. בסוף התהליך תקבל **Web App URL** – העתק הצידה. זוהי כתובת ה-API הראשי של המערכת!

## חבילה 3: שרת ההודעות ווטסאפ (Render Cloud Bridge)
צד הקוד של הקישור לוואטסאפ מנוהל באמצעות Node.js, ועולה לשרת יציב כדי לפעול 24/7. על מנת למנוע מאה שעות של ניתוקים או הזדקקות ל"סריקת ברקוד" כל יום מחדש — משתמשים ב-MongoDB לשמירת Session חוקי.

### שלב א': הכנת המסד לחיבורי וואטסאפ
1. פתח משתמש במערכת [MongoDB Atlas](https://www.mongodb.com/cloud/atlas/register).
2. צור אשכול (Cluster) **חינמי** ב-M0 Tier.
3. במסך האבטחה תחת `Network Access`, אפשר גישה לכל כתובת `0.0.0.0/0`.
4. הכרחי: בצע **Connect** ל-Cluster, והעתק את מחרוזת החיבור (`mongodb+srv://user:pass@cluster.mongodb.net/...`).

### שלב ב': הרצת השרת Render
1. העלה את התוכן של תיקיית ה-`bridge` ל-GitHub פרטי משלך (שחק תמיד באזור מוגן).
2. פתח חשבון בשרת החינמי [Render](https://render.com).
3. לחץ על הוספת שירות מסוג **Web Service**, והיכנס למאגר ה-GitHub שבנית בצעד 1.
4. **הגדרות אופרטיביות בסביבת הריצה (Environment):**
   * `MONGODB_URI`: הדבק את כתובת ה-MongoDB שקיבלת בשלב הקודם (הקפד לכלול את הסיסמה לאשכול בלי סוגריים מסביבה).
   * `BRIDGE_API_KEY`: הסיסמה שהגדרנו גם ב-GAS מקודם (שלב 2, סעיף 4). חייבת להיות בדיוק אותו הסטרינג.
   * `GAS_SCRIPT_URL`: ה-Web App URL מתוך הענן של גוגל Apps Script ששמרנו.
   * `CORS_ORIGINS`: הדומיינים מהם ניתן לגשת לשרת (תוכל לשים * בשלבי פיתוח ראשוניים).
   * `PUPPETEER_CACHE_DIR`: הגדר כ-`/opt/render/project/puppeteer` למהירות וחיסכון.

> [!NOTE]
> מומלץ על Render Tier של 7$ אם קופה/עיבוד הלוואנד של האפליקציה דורשת משאבים שנוטים לחרוג ממטמון ה-512MB החינמיים. התראות הטלגרם יעזרו לפקח על זה.

## חבילה 4: סביבת המשתמשים (Frontend PWA) - Netlify / Vercel
אפליקציות הלקוחות, הנהגים וההנהלה נבנו בפרוטוקול Vite כאפליקציית דף יחיד מהירה (SPA \ PWA).

1. בתוך התיקיה הראשית בפרויקט המחשב, העתק/שנה את קובץ ה-`.env.example` ל-`.env` להזנת מפתחות הפיירבייס:
   ```env
   VITE_FIREBASE_API_KEY=המפתח_מגוגל_קונסול
   VITE_FIREBASE_AUTH_DOMAIN=taxi-bridge-prod.firebaseapp.com
   VITE_FIREBASE_PROJECT_ID=taxi-bridge-prod
   VITE_FIREBASE_DATABASE_URL=https://taxi-bridge-prod-default-rtdb.europe-west1.firebasedatabase.app/
   ```
2. פתח חלון פקודות בתיקיית הלקוח (CMD / Terminal) והרץ:
   * `npm install` להתקנת הספריות והמודולים.
   * `npm run build` ליצירת תיקיית ההפצה המכווצת (תיקיית ה-`dist/`).
3. **העלאה לראווה:** גרור ושחרר את תיקיית ה-`dist` שנוצרה לך ישר אל שירות העלאה כגון [Netlify Drop](https://app.netlify.com/drop) או התחבר ישירות ל-GitHub ב-Netlify כדי להריץ את ה-Build אוטומטית בענן בכל עדכון גרסה עתידי.

### כניסה לביצוע: סריקת ברקודי מפעיל
הפעולה הראשונה שאחראית לאונליין במערכת היא כניסה של המסופים. גש לדפדפן (לשרת ה-Render שפרסמת) והזן: 
`https://YOUR-RENDER-URL.com/qr?role=dispatcher&key=YOUR_BRIDGE_API_KEY`

סרוק עם תכנת וואטסאפ במכשיר המיועד. חזור על הפעולה עם `role=passenger` ו `role=driver` בכל ווסטאפ יעודי בהתאמה. 
הכל נסרק בגוגל אטלס? מעולה - המערכת רצה לעד ואין צורך בסריקות מחדש אלא אם טלפון נותק ידנית מהאפליקציה על המכשיר.
